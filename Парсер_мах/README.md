# Сборщик новостей MAX

Скрипт читает активные MAX-источники с листа `Источники` по ссылке из `table.txt`,
получает публикации через клиентский протокол MAX и записывает их на лист `Новости`
через Google Sheets API. Чтение источников и новостей тоже выполняется через API;
таблица может быть закрытой. Нужен JSON-ключ сервисного аккаунта Google с доступом
к таблице — см. [GOOGLE_SETUP.md](GOOGLE_SETUP.md). Chromium нужен только для MAX.

## Пример таблицы

[Google-таблица с примерами данных и справочниками](https://docs.google.com/spreadsheets/d/1n9jpuaGPh9oeSYoQsZR-9I_P36q-S-2jOTLhCz9FpVo/edit?usp=sharing).
Перед запуском создайте свою копию и укажите её ссылку в `table.txt`.
Порядок копирования и настройки доступа — в общем [README](../README.md#пример-google-таблицы).
Используйте свои ключи GigaChat (для фильтра и классификатора) и Google.


## Запуск

Перед первым запуском установите зависимости и настройте Google API по
[инструкции](GOOGLE_SETUP.md). Скопируйте `table.example.txt` в `table.txt`
и укажите ссылку своей таблицы. Локальный ключ и `table.txt` исключены из Git.

```bash
source .env/bin/activate
python main.py
```

По умолчанию собираются и записываются публикации **за сегодня по МСК**.
Выбор периода (обе даты включительно):

```bash
python main.py --from-date 2026-09-05 --to-date 2026-09-08
```

Проверка доступа к таблице без запуска MAX и без записи:

```bash
python main.py --check-sheet
```

Проверка сбора MAX без записи (Google-ключ всё равно нужен для чтения источников;
дубли в этом режиме не анализируются):

```bash
python main.py --dry-run
```

Один источник (точное название из таблицы):

```bash
python main.py --source 'БНК'
```

`--write-sheet` сохранён как необязательный совместимый флаг. `--headless` скрывает
Chrome, но при необходимости повторного входа в аккаунт Мах следует запустить без этого флага.
Не запускайте две копии одновременно и не закрывайте Chrome во время работы.

## Как это работает

Chromium открывается только для сохранённой пользовательской сессии MAX.
Вход в Google в браузере не нужен.
Если потребуется вход, скрипт ждёт QR-авторизацию до пяти минут. Сессия хранится в
`.data/max-profile`; отдельно извлекать или вводить токен MAX не требуется.

Сборщик отправляет только две операции по существующему WebSocket: определение
канала по ссылке и чтение истории. Поиск по названию, прокрутка постов и кнопка
«Переслать» для сбора не используются. Это внутренний протокол MAX, который может
измениться. Браузер по-прежнему нужен для авторизации и поддержания соединения.

История читается порциями, с проверкой временных границ и перекрытием страниц для
исключения пропусков на границе. Паузы между страницами — 1–2 секунды, регулируются
`--delay-min` и `--delay-max`. Публикации без текста сохраняются со ссылкой, датой,
заголовком `Без текста` и пустым текстом. Для пересланного поста без своей подписи
используется доступный текст оригинала. Фото и видео не скачиваются.

## Что записывается

- A — Максим; (в коде можете поменять имя сборщика новостей: Парсер_мах –> max_news –> sheet_plan.py)
- B — дата сбора;
- E — дата публикации;
- G — точное название источника из первого листа;
- H — прямая ссылка на пост;
- J — первое предложение / первая строка;
- M — полный текст.

Остальные столбцы не изменяются. Порция до 100 публикаций записывается одним
атомарным запросом Sheets API: ссылки и остальные поля применяются вместе.
Затем все записанные значения проверяются чтением через API. Даты сохраняются
как даты с форматом `dd.MM.yyyy`, текст — буквально, даже если начинается с `=`.
Если в листе заканчиваются строки, они добавляются в том же запросе.
Заполненные значения существующих строк, в том числе ручные правки и формулы,
сохраняются; дополняются только пустые поля.

## Проверка дублей

Сначала проверяется прямая ссылка в H. Если она уже есть, новая строка не создаётся,
а пустые поля существующей строки при необходимости дополняются.

Для новой ссылки дополнительно сравнивается полный текст с M всех существующих
новостей, независимо от канала и даты, а также с новыми публикациями текущей порции.
Лишние пробелы, неразрывные пробелы, переносы строк, эмодзи, невидимые
форматирующие символы и эквивалентное Unicode-написание не влияют на совпадение.
Так исходный пост распознаётся и после удаления смайликов фильтром из M. Регистр, пунктуация, подписи и ссылки остаются значимыми.
Пустые тексты не считаются одинаковыми публикациями.

При совпадении текста новая публикация пропускается: остаётся источник и ссылка
уже записанной новости, либо первой принятой в текущем сборе. Это не обязательно
автор оригинала. Число пропусков видно в терминале. Существующие дубли не удаляются.
Сходные по смыслу тексты, репосты с добавленным комментарием или другой подписью
этот механизм не объединяет. Если текст в M изменён вручную, сравнение идёт с текущим содержимым M,
а не с исходным текстом. Фильтр перед отбором очищает M от смайликов; парсер при сравнении
применяет ту же очистку. Сам парсер записывает исходный текст MAX.

## Структура таблицы

Лист `Источники`: заголовки в строке 5, в пределах A:M. Обязательны `Название`,
`Основная ссылка`, `Платформа`, `Активность`. Выбираются строки с платформой `MAX`
(латиницей), активностью `активен`, `активный` или `да` и ссылкой `https://max.ru/...`.

Лист `Новости`: не менее 21 столбца (A:U), A5 — `Сборщик`, B5 — `Дата сбора`.
Данные начинаются с шестой строки; расположение записываемых столбцов фиксировано
выше. Имя сборщика `Максим` задано в `max_news/sheet_plan.py`.
Перед записью таблица перечитывается для обнаружения изменений. Не запускайте
одновременно парсер и фильтр и не переставляйте строки во время записи:
API не предоставляет блокировку от параллельных редакторов.

## Остановка и повторный запуск

Можно остановить скрипт через Ctrl+C. Повторите ту же команду с тем же периодом:
публикации будут прочитаны из MAX заново, ссылки сверены с таблицей. Уже записанные
посты не дублируются, незаполненные поля частичных строк дополняются. Повторный
запуск в течение дня проверяет все каналы снова, включая новые посты.

**Локального архива новостей нет.** Посты хранятся в памяти до записи. Браузер может вести собственный кеш; скрипт не сохраняет JSONL/CSV с публикациями.

Если удалить строку из таблицы и повторить период, включающий эту публикацию,
она будет добавлена снова, если в таблице не осталось другой новости с тем же текстом. При запуске только за сегодня старые даты не переносятся.
Если пост исчезнет из MAX до повторного запуска, восстановить его без архива нельзя.

В терминале видны результаты по каналам и подтверждённые записи. Код завершения 0
означает, что все каналы проверены; 1 — ошибка / неполный сбор; 130 — остановка.
При ошибке записи скрипт останавливается. Запрос записи не повторяется автоматически:
при потере ответа он мог уже выполниться. Повторный запуск сначала прочитает
фактическую таблицу и проверит дубли. При ошибке одного канала проверяет остальные.

## Файлы проекта

- `main.py` — запуск, выбор периода и источников.
- `login_max.py` — отдельный вход в MAX без Google API.
- `max_news/auth.py` — ожидание входа и готовности веб-приложения MAX.
- `max_news/protocol.py`, `api_collector.py` — чтение публикаций.
- `max_news/google_sheets.py`, `sheet_plan.py` — API таблицы, дубли и запись.
- `max_news/sources.py`, `models.py`, `text.py` — источники, структуры данных и заголовки.
- `tests/` — локальные тесты без доступа к MAX и Google.

## Мега-парсер (Excel + GigaChat, без Google Sheets)

`mega_parser.py` — отдельный от `main.py` пайплайн: источники читаются из локального
`Мониторинг_Источники.xlsx`, результат копится в `news_database.db` (SQLite) и
выгружается в `Мониторинг_Новости_заполненный.xlsx`. Каждая новость дополнительно
проходит через GigaChat (фильтр релевантности + извлечение фактов).

```bash
python mega_parser.py
```

Без флагов запуск открывает консольное меню (1 — запустить сбор, 2 — чёрный
список источников, 3 — пути к файлам, 4 — период поиска новостей, 5 — экспорт по
источникам, 6 — выход); для планировщика/автоматизации, где меню ждать некому,
используйте флаги ниже — они выполняют действие и завершаются без меню.

Источники по столбцу `Платформа`/ссылке распределяются на три движка:
обычные сайты (`requests`, многопоточно), MAX (Playwright + `.data/max-profile`,
вход через `login_max.py`) и Telegram (Playwright + `.data/telegram-profile`,
вход через `login_telegram.py` — тот же принцип, что у MAX). Каждый движок можно
запустить отдельно — в меню пункт 1 открывает подменю (все три / только WEB /
только MAX / только Telegram), в скриптовом режиме — флаг `--only`:

```bash
python mega_parser.py --run --only telegram        # только Telegram
python mega_parser.py --run --only web max         # WEB и MAX, без Telegram
```

Частичный запуск (не все три движка сразу) не продвигает дату для
инкрементального окна (см. ниже) — иначе пропущенные в этот раз движки могли бы
потерять часть периода при следующем автоматическом запуске. Дата продвигается
только когда отработали все три этапа за один раз.

### Отдельный файл по каждому источнику

Каждая новость в БД помечена, каким движком собрана (`parsed_news.platform`:
`web`/`max`/`telegram`). Файл экспорта следует за тем, что реально запускали:
собрали все три движка сразу (пункт 1 меню без сужения, `--run` без `--only`) —
один общий `Мониторинг_Новости_заполненный.xlsx`, как раньше. Собрали не все —
отдельный файл на каждый реально запущенный в этот раз движок
(`Мониторинг_Новости_заполненный_web.xlsx`, `..._max.xlsx`, `..._telegram.xlsx`;
та же структура/шаблон, что у общего файла):

```bash
python mega_parser.py --run --only telegram        # соберёт и сразу выгрузит только ..._telegram.xlsx
python mega_parser.py --run --only web max         # выгрузит ..._web.xlsx и ..._max.xlsx, без общего файла
```

Отдельно, без нового сбора — переэкспортировать уже накопленное в БД тем же
разбиением можно через меню (пункт 5 «Экспорт по источникам») или флагом
`--export-only` (**не запускает сбор**, только выгружает):

```bash
python mega_parser.py --export-only telegram
```

Новости, сохранённые ДО появления этой возможности, не помечены платформой
(`platform IS NULL`) — это нельзя восстановить задним числом, так как раньше
это нигде не логировалось. В раздельный экспорт такие старые строки не
попадут; общий `Мониторинг_Новости_заполненный.xlsx` (без фильтра) их
по-прежнему включает.

Ключ GigaChat не хранится в коде: возьмите переменную окружения
`GIGACHAT_CREDENTIALS` или создайте `gigachat_credentials.txt` рядом со скриптом
(скопируйте `gigachat_credentials.example.txt` и впишите свой ключ; файл в
`.gitignore`).

Источник, у которого подряд накопилось несколько провалов сети, уходит в
локальный чёрный список и дальше пропускается без повторных попыток. В меню это
пункт 2 (посмотреть/очистить весь список/очистить один источник); в скриптовом
режиме — флаги:

```bash
python mega_parser.py --run                    # сбор сразу, без меню (для планировщика)
python mega_parser.py --list-blacklist         # что сейчас в чёрном списке
python mega_parser.py --reset-blacklist        # сбросить полностью
python mega_parser.py --reset-blacklist "БНК"  # сбросить один источник по названию/ссылке
```

Источник также сам выходит из чёрного списка при первой же успешной загрузке —
ручной сброс нужен, если вы поправили ссылку в таблице и хотите проверить
источник немедленно, не дожидаясь следующего планового запуска.

### Пути к файлам

Все четыре пути (источники, шаблон новостей, итоговый файл, база данных)
переопределяются двумя способами:

- **Флагами** (разовое, для конкретного запуска/планировщика, не сохраняется):
  ```bash
  python mega_parser.py --run --sources other_sources.xlsx --db test.db
  ```
- **Меню → «3. Пути к файлам»** (постоянное — сохраняется в `mega_parser_paths.json`
  рядом со скриптом, подтягивается при каждом следующем запуске автоматически;
  пункт 5 в этом меню сбрасывает всё обратно к путям по умолчанию и удаляет файл).
  Флаг, если он передан, всё равно имеет приоритет над сохранённым в меню путём.

Полезно для тестового прогона на другом наборе источников или для отдельной
БД, не трогая боевую `news_database.db`. Если файл шаблона (`--news-template`
или пункт меню «Шаблон новостей») не найден по указанному пути — экспорт всё
равно пройдёт, но с предупреждением в логе: итоговый файл получится с голыми
заголовками, без форматирования, инструкций и выпадающих списков из шаблона.

### Инкрементальное окно сбора

`START_DATE` в коде (2026-07-01) — это нижняя граница проекта, а не окно
каждого запуска. Дата фактического начала сбора хранится в БД (`run_state`,
обновляется при успешном завершении) и на каждом следующем запуске
пересчитывается как «дата предыдущего запуска минус 2 дня нахлёста», но не
раньше `START_DATE`. Это видно в первой строке лога каждого запуска
(`📅 Окно сбора: с ... по ...`). Смысл — не гонять MAX/Telegram-прокрутку через
всю историю с июля при каждом запуске, а проверять только то, что могло
появиться с прошлого раза.

Чтобы разово задать другое окно (например, перепроверить конкретный месяц) —
меню → «4. Период поиска новостей»: там можно задать дату начала и/или
окончания вручную. Ручная дата действует **один раз**, на ближайший запуск —
после него автоматически возвращается инкрементальный режим (иначе окно
«застряло» бы навсегда на этой дате и не продвигалось дальше). Пункт 3 в этом
меню сбрасывает ручную дату сразу, без запуска сбора.
