# Сборщик новостей MAX

Скрипт читает активные MAX-источники с листа `Источники` по ссылке из `table.txt`,
получает публикации через клиентский протокол MAX и записывает их на лист `Новости`
через Google Sheets API. Чтение источников и новостей тоже выполняется через API;
таблица может быть закрытой. Нужен JSON-ключ сервисного аккаунта Google с доступом
к таблице — см. [GOOGLE_SETUP.md](GOOGLE_SETUP.md). Chromium нужен только для MAX.

## Пример таблицы

[Google-таблица с примерами данных и справочниками](https://docs.google.com/spreadsheets/d/1n9jpuaGPh9oeSYoQsZR-9I_P36q-S-2jOTLhCz9FpVo/edit?usp=sharing).
Перед запуском создайте свою копию и укажите её ссылку в `table.txt`.
Порядок копирования и настройки доступа — в общем [README](../README.md#пример-google-таблицы).
Используйте свои ключи GigaChat (для фильтра и классификатора) и Google.


## Запуск

Перед первым запуском установите зависимости и настройте Google API по
[инструкции](GOOGLE_SETUP.md). Скопируйте `table.example.txt` в `table.txt`
и укажите ссылку своей таблицы. Локальный ключ и `table.txt` исключены из Git.

```bash
source .env/bin/activate
python main.py
```

По умолчанию собираются и записываются публикации **за сегодня по МСК**.
Выбор периода (обе даты включительно):

```bash
python main.py --from-date 2026-09-05 --to-date 2026-09-08
```

Проверка доступа к таблице без запуска MAX и без записи:

```bash
python main.py --check-sheet
```

Проверка сбора MAX без записи (Google-ключ всё равно нужен для чтения источников;
дубли в этом режиме не анализируются):

```bash
python main.py --dry-run
```

Один источник (точное название из таблицы):

```bash
python main.py --source 'БНК'
```

`--write-sheet` сохранён как необязательный совместимый флаг. `--headless` скрывает
Chrome, но при необходимости повторного входа в аккаунт Мах следует запустить без этого флага.
Не запускайте две копии одновременно и не закрывайте Chrome во время работы.

## Как это работает

Chromium открывается только для сохранённой пользовательской сессии MAX.
Вход в Google в браузере не нужен.
Если потребуется вход, скрипт ждёт QR-авторизацию до пяти минут. Сессия хранится в
`.data/max-profile`; отдельно извлекать или вводить токен MAX не требуется.

Сборщик отправляет только две операции по существующему WebSocket: определение
канала по ссылке и чтение истории. Поиск по названию, прокрутка постов и кнопка
«Переслать» для сбора не используются. Это внутренний протокол MAX, который может
измениться. Браузер по-прежнему нужен для авторизации и поддержания соединения.

История читается порциями, с проверкой временных границ и перекрытием страниц для
исключения пропусков на границе. Паузы между страницами — 1–2 секунды, регулируются
`--delay-min` и `--delay-max`. Публикации без текста сохраняются со ссылкой, датой,
заголовком `Без текста` и пустым текстом. Для пересланного поста без своей подписи
используется доступный текст оригинала. Фото и видео не скачиваются.

## Что записывается

- A — Максим; (в коде можете поменять имя сборщика новостей: Парсер_мах –> max_news –> sheet_plan.py)
- B — дата сбора;
- E — дата публикации;
- G — точное название источника из первого листа;
- H — прямая ссылка на пост;
- J — первое предложение / первая строка;
- M — полный текст.

Остальные столбцы не изменяются. Порция до 100 публикаций записывается одним
атомарным запросом Sheets API: ссылки и остальные поля применяются вместе.
Затем все записанные значения проверяются чтением через API. Даты сохраняются
как даты с форматом `dd.MM.yyyy`, текст — буквально, даже если начинается с `=`.
Если в листе заканчиваются строки, они добавляются в том же запросе.
Заполненные значения существующих строк, в том числе ручные правки и формулы,
сохраняются; дополняются только пустые поля.

## Проверка дублей

Сначала проверяется прямая ссылка в H. Если она уже есть, новая строка не создаётся,
а пустые поля существующей строки при необходимости дополняются.

Для новой ссылки дополнительно сравнивается полный текст с M всех существующих
новостей, независимо от канала и даты, а также с новыми публикациями текущей порции.
Лишние пробелы, неразрывные пробелы, переносы строк, эмодзи, невидимые
форматирующие символы и эквивалентное Unicode-написание не влияют на совпадение.
Так исходный пост распознаётся и после удаления смайликов фильтром из M. Регистр, пунктуация, подписи и ссылки остаются значимыми.
Пустые тексты не считаются одинаковыми публикациями.

При совпадении текста новая публикация пропускается: остаётся источник и ссылка
уже записанной новости, либо первой принятой в текущем сборе. Это не обязательно
автор оригинала. Число пропусков видно в терминале. Существующие дубли не удаляются.
Сходные по смыслу тексты, репосты с добавленным комментарием или другой подписью
этот механизм не объединяет. Если текст в M изменён вручную, сравнение идёт с текущим содержимым M,
а не с исходным текстом. Фильтр перед отбором очищает M от смайликов; парсер при сравнении
применяет ту же очистку. Сам парсер записывает исходный текст MAX.

## Структура таблицы

Лист `Источники`: заголовки в строке 5, в пределах A:M. Обязательны `Название`,
`Основная ссылка`, `Платформа`, `Активность`. Выбираются строки с платформой `MAX`
(латиницей), активностью `активен`, `активный` или `да` и ссылкой `https://max.ru/...`.

Лист `Новости`: не менее 21 столбца (A:U), A5 — `Сборщик`, B5 — `Дата сбора`.
Данные начинаются с шестой строки; расположение записываемых столбцов фиксировано
выше. Имя сборщика `Максим` задано в `max_news/sheet_plan.py`.
Перед записью таблица перечитывается для обнаружения изменений. Не запускайте
одновременно парсер и фильтр и не переставляйте строки во время записи:
API не предоставляет блокировку от параллельных редакторов.

## Остановка и повторный запуск

Можно остановить скрипт через Ctrl+C. Повторите ту же команду с тем же периодом:
публикации будут прочитаны из MAX заново, ссылки сверены с таблицей. Уже записанные
посты не дублируются, незаполненные поля частичных строк дополняются. Повторный
запуск в течение дня проверяет все каналы снова, включая новые посты.

**Локального архива новостей нет.** Посты хранятся в памяти до записи. Браузер может вести собственный кеш; скрипт не сохраняет JSONL/CSV с публикациями.

Если удалить строку из таблицы и повторить период, включающий эту публикацию,
она будет добавлена снова, если в таблице не осталось другой новости с тем же текстом. При запуске только за сегодня старые даты не переносятся.
Если пост исчезнет из MAX до повторного запуска, восстановить его без архива нельзя.

В терминале видны результаты по каналам и подтверждённые записи. Код завершения 0
означает, что все каналы проверены; 1 — ошибка / неполный сбор; 130 — остановка.
При ошибке записи скрипт останавливается. Запрос записи не повторяется автоматически:
при потере ответа он мог уже выполниться. Повторный запуск сначала прочитает
фактическую таблицу и проверит дубли. При ошибке одного канала проверяет остальные.

## Файлы проекта

- `main.py` — запуск, выбор периода и источников.
- `login_max.py` — отдельный вход в MAX без Google API.
- `max_news/auth.py` — ожидание входа и готовности веб-приложения MAX.
- `max_news/protocol.py`, `api_collector.py` — чтение публикаций.
- `max_news/google_sheets.py`, `sheet_plan.py` — API таблицы, дубли и запись.
- `max_news/sources.py`, `models.py`, `text.py` — источники, структуры данных и заголовки.
- `tests/` — локальные тесты без доступа к MAX и Google.

## Мега-парсер (WEB + MAX + Telegram + GigaChat, без Google Sheets)

`mega_parser.py` — отдельный от `main.py` пайплайн: не читает и не пишет Google
Sheets вообще. Источники — локальный `Мониторинг_Источники.xlsx`, результат —
`news_database.db` (SQLite) и Excel-файл(ы) на выходе. Каждая найденная
кандидат-новость дополнительно проходит через GigaChat: сначала фильтр
релевантности (мусор/реклама/афиши — не собирать), затем извлечение фактов
(категория, стадия, цифры, лица, организации, ИНН, объект) для прошедших фильтр.

### Быстрый старт

```bash
python mega_parser.py
```

Без флагов открывается консольное меню — интерактивный режим для ручного
запуска:

```
╔════════════════════════════════════════╗
║          МЕГА-ПАРСЕР НОВОСТЕЙ          ║
╠════════════════════════════════════════╣
║ 1. Запустить сбор новостей             ║
║ 2. Чёрный список источников            ║
║ 3. Пути к файлам                       ║
║ 4. Период поиска новостей              ║
║ 5. Экспорт по источникам (WEB/MAX/Telegram отдельно) ║
║ 6. Выход                               ║
╚════════════════════════════════════════╝
```

Для планировщика/автоматизации, где меню ждать некому, используйте флаги (см.
таблицу ниже) — любой из них переводит скрипт в скриптовый режим: делает ровно
то, что попросили, и завершается без меню.

### Три движка сбора

Каждая строка `Мониторинг_Источники.xlsx` (лист «Источники», заголовки в
строке 5, обязательны колонки `Основная ссылка`, `Название`, `Муниципалитет`,
`Активность`, `Платформа`) распределяется по одному из трёх движков —
проверяется `Платформа` и/или сама ссылка:

| Движок | Признак в таблице | Как собирает |
|---|---|---|
| **WEB** | всё, что не MAX и не Telegram | `requests` + `BeautifulSoup`, многопоточно (`MAX_WORKERS = 8` потоков на список ссылок одного источника). Заходит на главную страницу источника, собирает все `<a href>`, отфильтровывает явный мусор (`/tag/`, `/category/`, `/search`, `/contacts`, `/about`, якоря, `mailto:`/`tel:`/`javascript:`), с каждой оставшейся ссылки пытается снять дату публикации (`article:published_time`, `<time datetime>`) и текст (`<h1>` + первые содержательные `<p>`). |
| **MAX** | `Платформа=MAX` или ссылка содержит `max.ru` | Playwright, headless, постоянный профиль браузера `.data/max-profile`. Не эмулирует клики — открывает существующий WebSocket мессенджера и говорит с ним напрямую через внутренний клиентский протокол (`max_news/protocol.py`, `api_collector.py`; описание протокола взято из [Max-API-Guide](https://github.com/PronikFire/Max-API-Guide) и [Komet](https://github.com/KometTeam/Komet)). Первый раз нужен ручной вход — см. «Вход в MAX и Telegram» ниже. |
| **Telegram** | `Платформа=Telegram` или ссылка `t.me`/`telegram.me` | Playwright, headless, постоянный профиль `.data/telegram-profile`, открывает `web.telegram.org/k/`. Сообщения ищутся по атрибуту `[data-mid]`, дата публикации — по `data-timestamp` (Unix-время) на самом этом узле — **не** по `<time datetime>`, которого в текущей разметке Telegram Web K нет (изменилось со стороны Telegram, проверено вживую 2026-09-23). Пригласительные/служебные ссылки (`t.me/+...`, `t.me/joinchat/...`) не поддерживаются протоколом веб-версии и всегда завершаются ошибкой источника — это не баг, такой источник в таблице нужно поправить на нормальную ссылку канала. |

Каждый движок можно запустить отдельно: в меню пункт 1 открывает подменю (все
три / только WEB / только MAX / только Telegram), в скриптовом режиме — флаг
`--only`:

```bash
python mega_parser.py --run --only telegram        # только Telegram
python mega_parser.py --run --only web max         # WEB и MAX, без Telegram
```

Частичный запуск (не все три движка сразу) не продвигает дату для
инкрементального окна (см. ниже) — иначе пропущенные в этот раз движки могли бы
потерять часть периода при следующем автоматическом запуске. Дата продвигается
только когда отработали все три этапа за один раз.

### GigaChat: авторизация, троттлинг, лимиты

`news_runtime/gigachat.py` (`GigaChatClient`) — не голый `requests`-вызов, а
обёртка с состоянием:

- Сама обновляет OAuth-токен (Basic-авторизация по ключу, эндпоинт
  `ngw.devices.sberbank.ru`) и хранит его до истечения.
- **Защёлка на отказ авторизации**: если ключ отклонён (HTTP 401/403), клиент
  один раз пробует обновить токен и повторить — если и это не помогло,
  запоминает отказ и дальше **весь оставшийся запуск** не ходит в GigaChat
  вообще, возвращая `None` мгновенно, без сетевых попыток. Раньше (до этого
  исправления) каждая статья заново пыталась достучаться с уже нерабочим
  ключом — сотни одинаковых `401` в логе на один прогон.
- Транзиентные ошибки (429, 5xx, таймаут, обрыв соединения) — до 3 попыток с
  экспоненциальной паузой (1с, 2с, 4с) на каждый HTTP-вызов.
- **Троттлинг не зависит от `MAX_WORKERS`**: `GIGACHAT_MIN_INTERVAL = 0.6`
  секунды — минимальный интервал между последовательными запросами к GigaChat,
  общий для всех потоков сразу (общий `Lock` в `mega_parser.py`). Рост числа
  потоков ускоряет только скачивание страниц, а не давление на GigaChat.
- Счётчик `stats.gigachat_calls` — сколько раз реально сходили в API за
  прогон, виден в итоговой сводке (`Запросов к GigaChat:`).

Ключ не хранится в коде. Порядок поиска: переменная окружения
`GIGACHAT_CREDENTIALS`, иначе файл `gigachat_credentials.txt` рядом со скриптом
(скопируйте `gigachat_credentials.example.txt` и впишите свой Basic-ключ в виде
`client_id_base64:client_secret_base64`). Оба варианта — только локально, файл
в `.gitignore`. Без ключа скрипт не запустится вообще (`RuntimeError` уже на
старте).

### Хранение: SQLite (`news_database.db`)

Четыре таблицы, все создаются/мигрируются автоматически при старте (`init_db()`):

- **`parsed_news`** — сохранённые новости: `url` (PK), `title`, `source`
  (название источника из таблицы), `municipality`, `pub_date`, `category`,
  `stage`, `summary`, `facts`, `persons`, `organizations`, `inn`, `location`,
  `created_at`, **`platform`** (`web`/`max`/`telegram` — каким движком
  собрана; строки, сохранённые до появления этой колонки, имеют `platform =
  NULL` и не участвуют в раздельном экспорте по источникам, см. ниже).
- **`rejected_urls`** — URL, которые не нужно проверять снова: `url` (PK),
  `reason`, `created_at`. Пишутся при явном отказе GigaChat (`is_relevant:
  false`, `reason` — объяснение модели) и при окончательном сетевом провале
  отдельной статьи (403/404/таймаут/обрыв после исчерпания повторов —
  `reason` начинается с `"Сеть: "`). Так мёртвая ссылка на странице источника
  (битый URL, ушедший в 404/403 сторонний ресурс) не скачивается заново на
  каждом следующем запуске.
- **`source_health`** — чёрный список источников: `source_url` (PK),
  `source_name`, `consecutive_failures`, `last_failed_at`, `blacklisted_at`.
- **`run_state`** — служебные пары ключ-значение: `last_run_date` (для
  инкрементального окна), `manual_start_date`/`manual_end_date` (разовое
  ручное окно, см. ниже).

`is_url_processed(url)` — единая проверка «уже видели» перед тем, как вообще
качать статью: смотрит и `parsed_news`, и `rejected_urls`. Отдельно —
нечёткая проверка по заголовку (`is_fuzzy_duplicate`, `difflib`, порог
схожести 0.85 против последних 300 сохранённых заголовков): ловит перепечатки
одной новости разными источниками. Совпадения по заголовку **не** пишутся ни в
одну таблицу (в отличие от совпадений по URL) — до GigaChat не доходит (расход
не тратится), но при следующем запуске тот же дубль снова найдётся и снова
залогируется как дубль — известное ограничение, не баг.

### Экспорт в Excel: общий файл или отдельно по источникам

Файл экспорта следует за тем, что реально запускали в этот раз:

- Собрали **все три движка сразу** (пункт 1 меню без сужения, `--run` без
  `--only`) — один общий `Мониторинг_Новости_заполненный.xlsx`.
- Собрали **не все** (например, только Telegram, или WEB+MAX без Telegram) —
  отдельный файл на каждый реально запущенный в этот раз движок
  (`Мониторинг_Новости_заполненный_web.xlsx`, `..._max.xlsx`,
  `..._telegram.xlsx`; та же структура/шаблон, что у общего файла, только
  строки отфильтрованы по `parsed_news.platform`).

```bash
python mega_parser.py --run --only telegram        # соберёт и сразу выгрузит только ..._telegram.xlsx
python mega_parser.py --run --only web max         # выгрузит ..._web.xlsx и ..._max.xlsx, без общего файла
```

Отдельно, без нового сбора — переэкспортировать уже накопленное в БД тем же
разбиением можно через меню (пункт 5 «Экспорт по источникам»: WEB / MAX /
Telegram по отдельности или все три сразу) или флагом `--export-only`
(**не запускает сбор**, только выгружает):

```bash
python mega_parser.py --export-only telegram
python mega_parser.py --export-only web max telegram
```

Если новостей для выбранной платформы в БД нет (например, все старые, ещё
без `platform`) — файл не создаётся, в лог пишется явное `ℹ️ Нет новостей
для экспорта`, вместо пустого файла с одними заголовками.

Структура файла (общего или по одному источнику) заимствуется из шаблона
`Мониторинг_Новости.xlsx` — лист «Новости», заголовки в строке 5, данные
дописываются начиная с первой пустой строки в столбце H (прямая ссылка) без
затирания уже заполненных вручную строк; дубли по прямой ссылке в H не
дублируются повторно. Если файла шаблона по указанному пути нет — экспорт всё
равно пройдёт, но с предупреждением в логе: итоговый файл получится с голыми
заголовками, без форматирования/инструкций/выпадающих списков из шаблона. Если
целевой файл на момент сохранения открыт в другой программе (типично — в
Excel) — экспорт логирует понятную ошибку и не выполняется в этот раз, но **не
роняет весь скрипт**: все новости уже надёжно лежат в БД, следующий успешный
запуск экспортирует их как обычно.

### Чёрный список источников

Источник, у которого подряд накопилось `SOURCE_FAILURE_THRESHOLD = 5`
провалов (сетевая ошибка листинга для WEB, исключение при сборе для MAX/
Telegram — но **не** просто отсутствие новых постов и **не** общий сбой всей
Telegram-сессии типа "требуется вход", это не вина конкретного источника),
уходит в локальный чёрный список и дальше пропускается без повторных попыток —
пока источник не выйдет из списка сам (первая же успешная загрузка сбрасывает
счётчик и снимает пометку) или его не сбросят вручную:

```bash
python mega_parser.py --list-blacklist         # что сейчас в чёрном списке
python mega_parser.py --reset-blacklist        # сбросить полностью
python mega_parser.py --reset-blacklist "БНК"  # сбросить один источник по названию/ссылке (частичное совпадение)
```

В меню — пункт 2 (показать список / очистить весь / очистить один источник).
Ручной сброс нужен, если вы поправили ссылку источника в таблице и хотите
проверить его немедленно, не дожидаясь пяти новых успешных запусков подряд,
чтобы алгоритм это заметил сам.

### Пути к файлам

Все четыре пути (источники, шаблон новостей, итоговый файл, база данных)
переопределяются двумя способами:

- **Флагами** (разовое, для конкретного запуска/планировщика, не сохраняется):
  ```bash
  python mega_parser.py --run --sources other_sources.xlsx --db test.db
  ```
- **Меню → «3. Пути к файлам»** (постоянное — сохраняется в `mega_parser_paths.json`
  рядом со скриптом, подтягивается при каждом следующем запуске автоматически;
  пункт 5 в этом меню сбрасывает всё обратно к путям по умолчанию и удаляет файл).
  Флаг, если он передан, всё равно имеет приоритет над сохранённым в меню путём.

Полезно для тестового прогона на другом наборе источников или для отдельной
БД, не трогая боевую `news_database.db`. При смене пути к БД через меню на нём
сразу создаются нужные таблицы (`init_db()`), можно сразу работать.

### Инкрементальное окно сбора

`START_DATE` в коде (2026-07-01) — это нижняя граница проекта, а не окно
каждого запуска: раньше этой даты новости не ищутся никогда, даже при первом
запуске. Дата фактического начала сбора хранится в БД (`run_state.last_run_date`,
обновляется только при завершении **полного** запуска — все три движка сразу,
см. выше) и на каждом следующем запуске пересчитывается как «дата предыдущего
запуска минус `INCREMENTAL_OVERLAP_DAYS = 2` дня нахлёста» (перекрытие — чтобы
не терять публикации на границе окна), но не раньше `START_DATE`. Видно в
первой строке лога каждого запуска: `📅 Окно сбора: с ... по ...`. Смысл — не
гонять MAX/Telegram-прокрутку через всю историю проекта при каждом запуске, а
проверять только то, что могло появиться с прошлого раза.

Чтобы разово задать другое окно (например, перепроверить конкретный месяц) —
меню → «4. Период поиска новостей»: можно задать дату начала и/или окончания
вручную (`ГГГГ-ММ-ДД`). Ручная дата действует **один раз**, на ближайший
запуск — после него `run()` сама сбрасывает её обратно в автоматический режим
(иначе окно «застряло» бы навсегда на этой дате и не продвигалось дальше при
следующих запусках). Пункт 3 в этом меню сбрасывает ручную дату сразу, без
запуска сбора.

### Вход в MAX и Telegram

Оба движка используют одну и ту же схему: постоянный профиль Chromium
(`.data/max-profile` / `.data/telegram-profile`), сохраняющий сессию между
запусками, плюс отдельный скрипт для ПЕРВОГО ручного входа:

```bash
python login_max.py        # откроет видимое окно Chrome, отсканируйте QR MAX
python login_telegram.py   # откроет видимое окно Chrome, отсканируйте QR/войдите в Telegram
```

Оба скрипта ждут подтверждения входа до 5 минут, печатают прогресс в консоль
(«ожидание входа…», затем «вход подтверждён, сессия сохранена») и завершаются
сами, как только вход подтверждён — закрывать окно раньше этого сообщения не
нужно (закроете раньше — получите понятную ошибку с просьбой повторить, а не
трейсбек). После этого `mega_parser.py` работает headless и повторного входа
не спрашивает, пока сессия жива. Если сессия истекла и `mega_parser.py`
запущен в headless-режиме сбора — движок логирует понятную ошибку
(«выполните `python login_max.py`» / «...`python login_telegram.py`») и
пропускает этот этап, не роняя весь прогон (WEB/остальные этапы всё равно
выполнятся, экспорт всё равно произойдёт).

### Итоговая сводка запуска

После каждого запуска (полного или частичного) печатается блок с цифрами
именно этого запуска (счётчики обнуляются в начале `run()`, не накапливаются
между несколькими запусками подряд в одной интерактивной сессии):

```
╔════════════════════════════════════════╗
║       ИТОГИ МЕГА-СБОРА НОВОСТЕЙ        ║
╠════════════════════════════════════════╣
║ Обычных сайтов (WEB):  ...             ║
║ Источников MAX:        ...             ║
║ Источников Telegram:   ...             ║
║ В чёрном списке (пропущ.): ...         ║
║ Всего новостей найдено:...             ║
║ Запросов к GigaChat:   ...             ║
║ Отклонено нейросетью:  ...             ║
║ Ошибок (сеть/API):     ...             ║

╚════════════════════════════════════════╝
```

### Логи

Консоль раскрашена по типу события (✅ зелёный/успех, 🗑️/жёлтый — пропуск,
❌/красный — ошибка, 🤖✨/голубой — обращение к GigaChat). Файл `parser.log`
рядом со скриптом дублирует те же сообщения без цвета и **дописывается** —
не перезаписывается между запусками, старые записи остаются.

### Справочник флагов командной строки

| Флаг | Что делает |
|---|---|
| `--run` | Запустить сбор сразу, без интерактивного меню (для планировщика) |
| `--only web max telegram` | Ограничить сбор указанными движками (один или несколько через пробел); требует `--run` |
| `--export-only web max telegram` | Не собирать ничего, только выгрузить уже накопленные в БД новости отдельными файлами по движкам |
| `--reset-blacklist [ИСТОЧНИК]` | Сбросить чёрный список: без значения — полностью, со значением — один источник по названию/ссылке |
| `--list-blacklist` | Показать чёрный список и выйти |
| `--sources ФАЙЛ` | Путь к таблице источников вместо `Мониторинг_Источники.xlsx` |
| `--news-template ФАЙЛ` | Путь к шаблону вместо `Мониторинг_Новости.xlsx` |
| `--output ФАЙЛ` | Путь к общему итоговому файлу вместо `Мониторинг_Новости_заполненный.xlsx` |
| `--db ФАЙЛ` | Путь к БД вместо `news_database.db` |

`--sources`/`--news-template`/`--output`/`--db` действуют вместе с любым из
остальных флагов (или без них — тогда откроют меню с уже подставленными
путями). Полная актуальная справка — `python mega_parser.py --help`.

### Файлы мега-парсера

- `mega_parser.py` — вся логика: меню, CLI, три движка сбора, GigaChat,
  чёрный список, инкрементальное окно, экспорт.
- `login_telegram.py` — отдельный вход в Telegram (по аналогии с `login_max.py`).
- `news_runtime/gigachat.py` — `GigaChatClient`: токен, защёлка на отказ
  авторизации, ретраи транзиентных ошибок.
- `news_runtime/social_browser.py` — `SocialBrowser`: общая браузерная логика
  для VK и Telegram (вход, ожидание готовности страницы, извлечение постов из
  HTML). VK-платформа реализована в коде на равных с Telegram, но в текущей
  таблице источников строк с `Платформа=VK` нет — не проверялась вживую.
- `gigachat_credentials.txt` / `gigachat_credentials.example.txt` — ключ
  GigaChat (первый — не в git, второй — шаблон).
- `mega_parser_paths.json` — пути, сохранённые через меню «Пути к файлам» (не
  в git, создаётся автоматически при первом сохранении пути через меню).
- `news_database.db` — SQLite, вся собранная история (не в git).
- `tests/test_gigachat_runtime.py`, `tests/test_social_browser.py` — тесты
  на `GigaChatClient`/`SocialBrowser` без реальной сети/браузера (моки).
