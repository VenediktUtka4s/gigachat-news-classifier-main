# Фильтр новостей через GigaChat и Google Sheets API

Фильтр работает **без браузера**. Он читает лист `Новости`, выбирает
публикации по **дате сбора в B**, передаёт текст из **M** в GigaChat и удаляет
неполезные новости через официальный Google Sheets API. Вывод — в терминале.
Перед классификацией удаляются строки с пустым после очистки текстом M,
а из оставшихся текстов M убираются смайлики. Дубли не проверяются,
остальные поля не заполняются.

## Пример таблицы

[Google-таблица с примерами данных и справочниками](https://docs.google.com/spreadsheets/d/1n9jpuaGPh9oeSYoQsZR-9I_P36q-S-2jOTLhCz9FpVo/edit?usp=sharing).
Перед запуском создайте свою копию и укажите её ссылку в `table.txt`.
Порядок копирования и настройки доступа — в общем [README](../README.md#пример-google-таблицы).
Используйте свои ключи GigaChat (для фильтра и классификатора) и Google;
реальные ключи не входят в репозиторий.


## Установка и первоначальная настройка

Для текущей версии нужны **macOS или Linux и Python 3.12**. На Windows запуск
без адаптации не поддерживается: `main.py` использует модуль `fcntl`.
Парсер MAX, Playwright, Chromium и аккаунт MAX для фильтра не нужны.

Скачайте код и откройте терминал в папке с `main.py`. Создайте отдельное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Все следующие команды выполняются в этой папке с активированным окружением.
В новом терминале снова выполните `source .venv/bin/activate`.

Создайте локальные настройки из примеров (один раз, если файлов ещё нет):

```bash
cp -n table.example.txt table.txt
cp -n api_key.example.txt api_key.txt
```

- В `table.txt` замените пример ссылкой своей Google-таблицы.
- В `api_key.txt` замените заглушку своим ключом авторизации GigaChat,
  одной строкой. Ключ должен соответствовать выбранному `--scope`.
- Настройте `google_credentials.json` по инструкции ниже.
- Проверьте критерии в `request.txt`: они предназначены для новостей
  муниципалитетов Республики Коми. Дополнительные правила находятся
  в `build_prompt()` файла `classifier.py`.
- Оставьте `russian_trusted_root_ca.pem` рядом с `main.py`: это публичный
  сертификат доверия.


## Настройка Google

В папке рядом с `main.py` нужен файл `google_credentials.json` — JSON-ключ
сервисного аккаунта, которому предоставлена роль редактора таблицы.
Пошаговая инструкция: [GOOGLE_SETUP.md](GOOGLE_SETUP.md).

При отсутствии ключа программа сразу сообщает об этом и останавливается,
не открывая Chrome и не отправляя новости в GigaChat.

## Запуск

В папке проекта с активированным окружением `.venv`:

```bash
python main.py --check-sheet
```

Проверка доступа выполняет только чтение Google Таблицы, без GigaChat и удаления.
Проверка десяти новостей через GigaChat без изменений таблицы:

```bash
python main.py --from-date 2026-09-03 --dry-run --limit 10
```

За диапазон дат сбора, обе границы включительно:

```bash
python main.py --from-date 2026-09-01 --to-date 2026-09-09
```

Без дат выбирается сегодняшний день по MСК. Только `--from-date` означает
ровно один день. `--to-date` без `--from-date` и обратный диапазон отклоняются.
Дата публикации в E не влияет на выбор. `--limit N` ограничивает число обработанных
строк, начиная с нижних. Старые новости вне периода сохраняются.

Повторный запуск снова проверяет оставшиеся новости указанного периода. Кеша решений нет. Новые строки, добавленные между запусками, учитываются по тому же фильтру.

## Структура Google-таблицы

Нужен лист `Новости`. В строке 5 должны находиться следующие заголовки A:M,
в указанном порядке; данные начинаются со строки 6:

| Столбец | Заголовок |
|---|---|
| A | Сборщик |
| B | Дата сбора |
| C | Основной муниципалитет |
| D | Дополнительные муниципалитеты |
| E | Дата публикации |
| F | Дата события |
| G | Источник |
| H | Прямая ссылка |
| I | Дополнительные ссылки |
| J | Заголовок |
| K | Категория |
| L | Стадия события |
| M | Краткое фактическое резюме |

Название M сохранено для совместимости с существующим шаблоном; модель
анализирует фактический текст этой ячейки. Даты сбора в B должны быть в формате
`ДД.ММ.ГГГГ`. При удалении новости удаляется вся строка,
включая дополнительные столбцы справа от M.

## GigaChat

- `api_key.txt` — один ключ авторизации GigaChat из личного кабинета.
- `request.txt` — основные критерии полезности; согласованные уточнения добавлены
  в `build_prompt()` файла `classifier.py`.
- `table.txt` — ссылка на Google Таблицу.
- `--model` — модель, по умолчанию `GigaChat-3-Ultra` (Ultra). Дописывать флаг для Ultra не нужно.
- `--scope` — тип доступа, по умолчанию `GIGACHAT_API_PERS`.
- `--list-models` — проверить ключ GigaChat и вывести модели. Доступ Google не нужен.

Для проверки доступных вашему аккаунту моделей (может не отвечать при некоторых активных VPN):

```bash
python main.py --list-models
```

Если модель по умолчанию недоступна, выберите доступную через `--model`.
Для другого типа аккаунта укажите подходящий `--scope`: `GIGACHAT_API_PERS`,
`GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`.

Каждая новость получает независимый запрос. Ответ — только `{"useful": true}`
или `{"useful": false}`. Цитаты и объяснения не запрашиваются. Неверный формат,
обрезанный ответ или ошибка API останавливают обработку, кроме описанных ниже случаев.
При сетевом сбое классификации (соединение, тайм-аут, передача ответа) запрос
той же новости повторяется до трёх раз с паузами 2, 5 и 10 секунд: максимум
четыре попытки. Повторы выводятся в терминал и журнал как `classification_retry`.
После четвёртой неудачи скрипт останавливается, текущая строка остаётся в таблице.
Получение токена, списка моделей, ошибки TLS, HTTP и некорректные ответы
автоматически не повторяются. Отдельное исключение —
`finish_reason=blacklist`: строка остаётся без изменений, в журнал записывается
`manual_review` (нужна ручная проверка), обработка продолжается. Такая строка
не считается классифицированной как полезная; её число выводится отдельно в итоге.
При повторном запуске за тот же период она снова отправляется на классификацию.
Модели передаются инструкция с критериями и текст M. Ссылка из H используется
только скриптом для журнала и терминала, отдельно в запрос не добавляется.
Если ссылка содержится внутри самого M, она остаётся частью отправляемого текста;
скрипт не открывает ссылки.
Качество классификации проверяется по ручной разметке; корректный JSON
сам по себе не доказывает правильность решения.

## Предварительная очистка M

Для строк выбранного периода по B (и с учётом `--limit`) сначала подготавливается
текст без Unicode-эмодзи, лишних пробелов и невидимых форматирующих символов.
Затем **до первого запроса классификации новости** удаляются все выбранные строки,
у которых подготовленный текст пуст. Это относится и к публикациям из одних смайликов.
Проверка доступности модели выполняется до этой очистки, чтобы не начинать изменения
при неверной настройке GigaChat.

У остальных выбранных строк очищенный текст записывается **в сам столбец M** через
Google Sheets API порциями до 100 ячеек, проверяется чтением и затем передаётся
модели. При сбое очистки запуск останавливается до классификации. При последующей
ошибке GigaChat уже подтверждённая очистка M и удаления пустых строк сохраняются.

Обрабатываются составные эмодзи, оттенки кожи и флаги. Замена пробелом предотвращает
склеивание слов: `ремонт🚧дороги` превращается в `ремонт дороги`. Цифра из `1️⃣`
становится обычной `1`; числа, знаки валют, ссылки, пунктуация и абзацы сохраняются.
Текстовые знаки ©, ®, ™ сохраняются. Обычные сочетания символов вроде `:)` не удаляются.
Слова не пересказываются и не сокращаются; заголовок в J не меняется.

`--dry-run` показывает предполагаемую очистку и удаления, отправляет модели
очищенный текст, но **не изменяет таблицу**. Старые новости вне периода и строки
за пределами `--limit` не очищаются. Ограничение количества применяется один раз
до удаления пустых строк: освободившиеся места не заполняются другими новостями.

Журнал содержит события `clean_text_pending`, `text_cleaned`, `would_clean_text`;
удаления без модели помечены `reason: empty_text`. Полный текст не записывается в журнал.

Полностью пустые строки пропускаются. Пустые C, F, K, L не являются основанием
для удаления. Занятая строка без корректной даты сбора останавливает запуск
до любых удалений: сначала нужно исправить дату.

## Как выполняется удаление

Один раз читаются метаданные листа и A5:M до конца сетки. Заголовки проверяются.
Пустые тексты удаляются снизу вверх отдельным проходом; оставшиеся выбранные
новости тоже классифицируются снизу вверх. Номера строк пересчитываются после
предварительных удалений.

Перед удалением через API читается маленький диапазон: целевая строка,
предыдущая и до двух следующих. Их значения A:M сравниваются с исходными.
Затем отправляется **один** `deleteDimension` с `dimension: ROWS`, точным ID
листа и индексом строки. После него повторно читается небольшой диапазон
и проверяется ожидаемый сдвиг. Остальные столбцы также удаляются вместе со строкой.
Вся таблица заново для каждого удаления не скачивается.

Ошибка записи, сети, авторизации или подтверждения останавливает скрипт.
Запрос удаления не повторяется автоматически, в том числе после HTTP 401.
Уже выполненные удаления сохраняются. При неопределённом результате сначала
проверьте таблицу перед повторным запуском.

Между запросами Sheets API выдерживается интервал не менее 1,1 секунды,
чтобы снизить риск превышения квоты. Ошибка 429 останавливает скрипт.
Ключи и токены не выводятся в журнал. Google-ключ не связан с ключом GigaChat.

Во время обработки не сортируйте и не редактируйте лист, не запускайте парсер.
Проверка диапазона обнаруживает изменения вокруг текущей строки, но не является
атомарной блокировкой таблицы. Параллельные запуски фильтра для одной таблицы
на этом компьютере блокируются файловым замком (macOS/Linux).

## Журнал и ошибки

`.data/run-*.jsonl` содержит период, модель, хеш инструкции, ссылку,
номер строки на момент операции и решение. `delete_pending` записывается
до операции, `deleted` — после подтверждения. Одинокий `delete_pending`
не доказывает ни успех, ни отсутствие удаления. Полного архива новостей нет.

Коды выхода: 0 — завершено, 1 — ошибка, 130 — остановка через Ctrl+C.
Если снова запустить MAX-парсер за период удалённых постов, он может добавить
их обратно: удалённой строки больше нет в таблице. Ссылки и тексты оставшихся
новостей проверяются на дубли, при сравнении текста парсер тоже игнорирует эмодзи.

## Сертификат GigaChat и зависимости

`russian_trusted_root_ca.pem` загружен по официальной инструкции:
https://developers.sber.ru/docs/ru/gigachat/certificates

Источник: https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt

Он объединяется с сертификатами `certifi` в `.data/gigachat-ca.pem` только для
клиента GigaChat. Системное хранилище не меняется, TLS-проверка включена.
Поддерживаются `--ca-bundle`, `REQUESTS_CA_BUNDLE`, `CURL_CA_BUNDLE`.

Зависимости отдельного окружения устанавливаются из `requirements.txt`,
как описано в начале README. Локальные тесты не обращаются к Google или GigaChat:

```bash
python -m pytest -q
```

Тесты проверяют фильтр дат, обход снизу вверх, двоичный ответ GigaChat,
точные индексы удаления Sheets API, сверку соседних строк, подтверждение
сдвига и отсутствие повторного удаления при ошибках.

Удаление Unicode-эмодзи реализовано через [emoji.replace_emoji](https://emoji-python.readthedocs.io/en/stable/#replacing-and-removing-emoji).
