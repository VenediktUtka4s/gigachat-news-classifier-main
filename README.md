# СБЕР практика — сбор и классификация новостей

В репозитории три Python-проекта:

| Папка | Назначение | Инструкция |
|---|---|---|
| `Парсер_мах` | Собирает публикации из активных источников MAX, записывает в Google Sheets, пропускает дубли по ссылке и тексту | [README парсера](Парсер_мах/README.md) |
| `Фильтр_новостей` | Очищает столбец M "Краткое фактическое резюме" (в нем хранится весь текст новости) на листе "Новости" от смайликов, удаляет строки с пустым текстом и фильтрует остальные новости через GigaChat Ultra | [README фильтра](Фильтр_новостей/README.md) |
| `Классификатор_новостей` | Структурирует полезные новости через GigaChat Ultra: муниципалитеты, категория, стадия, дата и дополнительные факты | [README классификатора](Классификатор_новостей/README.md) |

## Подготовка

Каждый проект устанавливается из своей папки по собственной инструкции.
Для фильтра и классификатора нужны macOS/Linux и Python 3.12; Windows пока не поддерживается
из-за использования `fcntl` (так указал Кодекс, у меня нет возможности проверить работу на Винде). Инструкция парсера также ориентирована на macOS/Linux.

- Скопируйте `table.example.txt` в локальный `table.txt` нужного проекта
  и укажите свою Google-таблицу с требуемой структурой.
- Настройте сервисный аккаунт Google и предоставьте ему права редактора таблицы:
  [для парсера](Парсер_мах/GOOGLE_SETUP.md),
  [для фильтра](Фильтр_новостей/GOOGLE_SETUP.md),
  [для классификатора](Классификатор_новостей/GOOGLE_SETUP.md).
- Для парсера установите Chromium и войдите в собственный аккаунт MAX.
- Для фильтра и классификатора создайте `api_key.txt` из `api_key.example.txt`, укажите
  собственный ключ GigaChat и проверьте доступность выбранной модели.

Настоящие ключи, локальные файлы `table.txt`, браузерные профили, журналы, кеши и
установленные окружения исключены из Git; Ссылка на согласованную таблицу-пример
опубликована ниже; В репозитории находятся только
исходники, тесты, инструкции и примеры настроек.

## Пример Google-таблицы

[Открыть таблицу-пример для парсера, фильтра и классификатора](https://docs.google.com/spreadsheets/d/1n9jpuaGPh9oeSYoQsZR-9I_P36q-S-2jOTLhCz9FpVo/edit?usp=sharing). Пример содержит некоторе количество источников и результат работы парсинга, фильтрации и классификации новостей.

Для собственной работы:

1. Откройте пример и создайте свою копию через **Файл → Создать копию**.
2. Сохраните листы, заголовки в строке 5, справочники и выпадающие списки.
   Настройте источники под свою задачу. Для начала без чужих новостей очистите
   значения примеров на листе «Новости», сохранив заголовки, формулы и проверки данных.
3. Предоставьте своему сервисному аккаунту Google права редактора **своей копии**.
4. Запишите ссылку на свою копию в локальный `table.txt` каждой программы.
5. Проверьте доступ командой `main.py --check-sheet` через окружение соответствующего проекта.

Запускайте программы на своей копии: фильтр удаляет строки, парсер и классификатор
записывают данные. Подробная структура описана в
[TABLE_SCHEMA.md](Классификатор_новостей/TABLE_SCHEMA.md).

## Порядок работы

1. Запустите парсер за нужные **даты публикации**. Он читает только активные
   источники с платформой `MAX`; остальные источники пропускает.
2. После окончания сбора запустите фильтр за нужные **даты сбора в B**.
   Он проверяет все новости этого периода независимо от платформы и сборщика.
3. После фильтра запустите классификатор за те же **даты сбора в B**.
   По умолчанию он заполняет только пустые C, D, F, K, L, N, O, P, R.
   Для явного пересчёта заполненных разрешённых полей есть `--overwrite`.

Все три программы запускайте последовательно для одной таблицы. Не сортируйте строки
во время обработки. Для проверки без изменения таблицы используйте `--dry-run`.

Парсер не удаляет уже существующие дубли, а предотвращает добавление новых.
Фильтр не хранит кеш решений: повторный запуск за тот же период снова
проверяет оставшиеся новости. Повторный сбор может вернуть удалённые публикации,
если их ссылки или совпадающие тексты больше не представлены в таблице.

Классификатор не определяет полезность повторно: он обрабатывает оставшиеся
строки периода. Отдельной отметки полезности в таблице нет.

## Скорость обработки

Ориентиры по журналам запусков 12–13 сентября 2026 года с `GigaChat Ultra`:

| Этап | Скорость |
|---|---|
| Парсер | Сбор новостей за день из 22 активных источников MAX занимает незначительное время относительно последующей обработки |
| Фильтр | В среднем около **2-3 секунд на новость**; в последнем завершённом проходе |
| Классификатор | В среднем около **6-8 секунды на новость**; |

Это время обработки с обращениями к API, проверками и записью в таблицу.
У фильтра скорость зависит от доли удалений и объёма очистки, у классификатора —
от количества записей, повторов и уже заполненных ячеек. Длительность сбора
зависит от количества публикаций и страниц истории.

## Пример полного запуска с замером времени

Сначала выполните установку и настройку каждого проекта по его README.
У парсера и классификатора команды ниже используют `.env`, у фильтра — `.venv`.
Окружения создаются отдельно и не входят в репозиторий.

В таблице примере: публикации с 1 июля по 12 сентября, собранные **12 сентября 2026 года**.
Начните в корне репозитория, выполняйте блоки по очереди и проверяйте итог
каждого запуска.

```bash
cd Парсер_мах
time .env/bin/python main.py --from-date 2026-07-01 --to-date 2026-09-12
```

Парсер требует установленного Chromium; окно не закрывайте до завершения.
Для сохранённого входа в MAX можно добавить `--headless`.
Если браузеры установлены в отдельную папку, используйте один и тот же путь
при установке и запуске, например из папки парсера:

```bash
env PLAYWRIGHT_BROWSERS_PATH="../.playwright-browsers" .env/bin/python -m playwright install chromium
time env PLAYWRIGHT_BROWSERS_PATH="../.playwright-browsers" .env/bin/python main.py --from-date 2026-07-01 --to-date 2026-09-12
```

После завершения сбора:

```bash
cd ../Фильтр_новостей
time .venv/bin/python main.py --from-date 2026-09-12 --to-date 2026-09-12
```

После завершения фильтра:

```bash
cd ../Классификатор_новостей
time .env/bin/python main.py --from-date 2026-09-12 --to-date 2026-09-12
```

Для предварительной проверки фильтра или классификатора добавьте `--dry-run --limit 3`.
Фильтр не сохраняет точку продолжения: после сбоя он снова проверяет оставшиеся
строки периода. Классификатор также не имеет автоматического продолжения по журналу;
при повторе заполненные ячейки сохраняются, но строки с пустыми дополнительными
полями могут анализироваться снова.

В выводе `time` показатель `total` (или `real`) — полное время команды.
`user` и `system` показывают процессорное время. Фильтр и классификатор также
сохраняют события с временем в `.data/run-*.jsonl`; парсер журнал времени не ведёт.
