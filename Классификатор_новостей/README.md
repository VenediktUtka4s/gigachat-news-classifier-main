# Классификатор полезных новостей

Второй проход после `Фильтр_новостей`: извлекает данные из текста M через
GigaChat Ultra и заполняет только C, D, F, K, L, N, O, P, R через Google Sheets API.
Браузер не используется. Строки не удаляются, исходный текст не переписывается.

## Пример таблицы

[Google-таблица с примерами данных и справочниками](https://docs.google.com/spreadsheets/d/1n9jpuaGPh9oeSYoQsZR-9I_P36q-S-2jOTLhCz9FpVo/edit?usp=sharing).
Перед запуском создайте свою копию и укажите её ссылку в `table.txt`.
Порядок копирования и настройки доступа — в общем [README](../README.md#пример-google-таблицы).
Используйте свои ключи GigaChat (для фильтра и классификатора) и Google;
реальные ключи не входят в репозиторий.


## Быстрая проверка

Запускайте команды из папки `Классификатор_новостей`. Перед первым запуском
выполните [установку](#установка-на-новом-компьютере), создайте окружение `.env`
и настройте свои ключи и ссылку на таблицу. Парсер и его окружение не требуются.

Проверить доступ, заголовки и все допустимые значения без запросов к модели:

```bash
.env/bin/python main.py --check-sheet
```

Проанализировать три новости и показать результат **без изменения таблицы**:

```bash
.env/bin/python main.py --from-date 2026-09-03 --to-date 2026-09-09 --dry-run --limit 3
```

Записать результаты для трёх новостей:

```bash
.env/bin/python main.py --from-date 2026-09-03 --to-date 2026-09-09 --limit 3
```

Для всего периода уберите `--limit`. Период включительный, **по дате сбора B**,
как у фильтра. Без `--to-date` обрабатывается один день, без дат — текущий день
по МСК. Порядок — снизу вверх. Лимит считает новости с текстом, переданные модели;
пустые и полностью заполненные строки его не расходуют.

В таблице нет поля с подтверждением полезности. Классификатор считает кандидатами
все оставшиеся строки выбранного периода, независимо от источника и сборщика.
Сначала завершите работу фильтра. Строки, оставленные фильтром для ручной проверки
(например, `blacklist`), также могут попасть в этот проход: программа не выдаёт их
за подтверждённо полезные и повторно полезность не оценивает.

## Разрешённые поля

Заголовки находятся в строке 5, новости начинаются со строки 6.

| Столбец | Поле | Правило |
|---|---|---|
| C | Основной муниципалитет | Место события → муниципалитет источника → Республика Коми |
| D | Дополнительные муниципалитеты | Только из справочника, без основного и повторов; через `; ` |
| F | Дата события | Настоящий тип даты Google Sheets с отображением `ДД.ММ.ГГГГ`, без текстового апострофа |
| K | Категория | Одна из разрешённых; `Другое`, если подходящей нет |
| L | Стадия события | Одна из разрешённых; при неопределённости — `Другое`, если оно включено в список |
| N | Ключевые цифры и факты | Краткие факты, по одному на строку |
| O | Упомянутые лица | Прямо названные в тексте лица, по одному на строку |
| P | Организации | Прямо названные организации, по одной на строку |
| R | Объект/населённый пункт | Указанный объект, адрес или населённый пункт |

Запись идёт адресно, только в разрешённые ячейки. A, B, E, G, H, I, J, M, Q,
S и последующие столбцы не входят в запросы записи. Форматирование и проверки
данных сохраняются; для F устанавливается формат даты `dd.mm.yyyy`.
Формулы в целевых ячейках программа не заменяет.

По умолчанию заполняются только пустые ячейки. Для пересчёта заполненных разрешённых
полей добавьте `--overwrite`; сначала удобно проверить его вместе с `--dry-run`.
Даже `--overwrite` не стирает ячейку, если модель вернула `null` или пустой список.
Пустые дополнительные сведения не считаются ошибкой. Решения не кешируются:
повторный запуск снова проверяет строки, где остались пустые разрешённые ячейки.

## Справочники и промпт

При каждом запуске программа проверяет листы `Новости`, `Источники`, `Справочники`:

- Муниципалитеты: непустые значения `Справочники!A4:A…`, после проверки заголовка.
- Категории и стадии: реальные правила выпадающих списков K6 и L6. При ознакомлении
  с таблицей подтверждены диапазоны `Справочники!B4:B18` и `Справочники!D4:D14`.
- Источники: название из G и муниципалитет из C листа `Источники`; ссылка H
  помогает различить одноимённые источники. Неизвестная или неоднозначная
  привязка даёт «Республика Коми», название источника не разбирается по догадке.

Проверены **21 муниципалитет, 15 категорий и 11 стадий**. Снимок списков для человека:
[TABLE_SCHEMA.md](TABLE_SCHEMA.md). Снимок не подменяет живые справочники при запуске.

Основной промпт: [request.txt](request.txt). Программа добавляет актуальные справочники
и передаёт их в JSON Schema с `strict: true` — механизм описан в
[документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).
Ответ проверяется повторно в Python: набор ключей, типы, точные значения, дата, повторы.
Произвольные категории никогда не заменяют допустимые значения.

Модель должна вернуть все девять ключей. Одиночные неизвестные значения — `null`,
списки — `[]`; категория обязательна. `main_municipality: null` включает подстановку
по источнику в коде. `event_stage: null` заменяется на `Другое`, если этот вариант
есть в актуальном списке стадий; заполненные ячейки сохраняются без `--overwrite`.

Стадия `Другое` находится в `Справочники!D14`. Для её использования
правила выпадающего списка L должны включать D14 (например, D4:D14).
Одного добавления строки в справочник недостаточно. Перед запуском `--check-sheet`
должен показывать `Другое` среди `stages`; в K6 и L6 должны быть правила списков.

Дата публикации E нужна только для интерпретации «сегодня», «вчера», «завтра»;
сама по себе она не становится датой события. Название источника не должно
превращаться в упомянутое лицо или организацию, если их нет в тексте.
Поэтому модель получает только текст и дату публикации; привязка источника
используется отдельно в коде для подстановки основного муниципалитета.

## Ошибки, журнал и одновременная работа

Некорректный ответ модели исправляется максимум двумя повторными запросами.
После третьей неудачи строка пропускается с `manual_review`, запись не выполняется.
`blacklist` сразу отправляется на ручную проверку. Для временных сетевых ошибок
генерации используются те же три повтора, что у фильтра: через 2, 5 и 10 секунд.
Ошибки авторизации, HTTP, доступа к Sheets и изменения строк останавливают запуск.

Перед записью повторно читаются справочники, заголовки и целевая строка;
проверяются правила конкретных ячеек. После записи результат сверяется чтением.
Запрос записи при неопределённом результате автоматически не повторяется.
Google Sheets не предоставляет здесь блокировку от ручного редактирования между
проверкой и записью: не сортируйте строки и не запускайте парсер во время обработки.

Два классификатора, а также классификатор и соседний `Фильтр_новостей` на этом
компьютере используют файловую блокировку для одной таблицы. Блокировка не
распространяется на другой компьютер и парсер.

Журналы: `.data/run-*.jsonl`. В них есть справочники, хеш промпта, решения,
адреса изменяемых ячеек, ошибки и подтверждения записи. `write_pending` без
`updated` требует проверки строки перед повторным запуском.

Коды выхода: `0` — завершено, `1` — остановка/ошибка API, `2` — завершено с
отклонёнными ответами или неопределённой стадией, `130` — остановка пользователем.

## Установка на новом компьютере

Нужны Python 3.12 и macOS/Linux (`fcntl`).

```bash
python3.12 -m venv .env
.env/bin/python -m pip install -r requirements.txt
```

Рядом с `main.py`:

- `api_key.txt` — ключ авторизации GigaChat (как в фильтре).
- `table.txt` — ссылка на Google-таблицу (как в фильтре).
- `google_credentials.json` — ключ сервисного аккаунта Google с доступом к таблице.

Создайте локальные файлы из примеров (существующие файлы не перезаписываются):

```bash
cp -n api_key.example.txt api_key.txt
cp -n table.example.txt table.txt
```

Замените заглушки своим ключом авторизации GigaChat и ссылкой на таблицу.
JSON-ключ Google создаётся отдельно или копируется из вашей установки фильтра.
Эти файлы исключены из Git и не поставляются с репозиторием.
Настройка сервисного аккаунта: [GOOGLE_SETUP.md](GOOGLE_SETUP.md).
Публичный `russian_trusted_root_ca.pem` используется только в клиенте GigaChat;
проверка TLS остаётся включённой.

Проверить доступные модели:

```bash
.env/bin/python main.py --list-models
```

По умолчанию `GigaChat-3-Ultra`. При необходимости доступны `--model`, `--scope`,
`--api-key-file`, `--criteria-file`, `--google-credentials`, `--spreadsheet-id`,
`--ca-bundle`. Ключи не печатаются в журнал и сообщения об ошибках.

Проверки программы:

```bash
.env/bin/python -m pytest -q
```

## Параметры команды

| Параметр | Назначение |
|---|---|
| `--from-date YYYY-MM-DD` | Начало периода по B; без параметра — сегодня по Москве |
| `--to-date YYYY-MM-DD` | Конец периода включительно; требует `--from-date` |
| `--dry-run` | Анализ через GigaChat и просмотр результата без записи |
| `--limit N` | Не более N новостей с текстом, снизу вверх |
| `--overwrite` | Разрешить пересчёт уже заполненных разрешённых полей |
| `--check-sheet` | Проверить структуру и справочники без модели и записи |
| `--list-models` | Показать доступные модели без чтения таблицы |
| `--model NAME` | Модель API; по умолчанию `GigaChat-3-Ultra` |
| `--scope NAME` | `GIGACHAT_API_PERS` (по умолчанию), `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` |
| `--api-key-file PATH` | Другой файл ключа GigaChat |
| `--criteria-file PATH` | Другой файл промпта |
| `--google-credentials PATH` | Другой JSON-ключ Google |
| `--spreadsheet-id ID_OR_URL` | Другая таблица вместо `table.txt` |
| `--ca-bundle PATH` | Доверенный PEM для соединения с GigaChat |

`--check-sheet` и `--list-models` нельзя использовать вместе.
Для просмотра пересчёта перед записью:

```bash
.env/bin/python main.py --from-date 2026-09-12 --dry-run --overwrite --limit 3
```

## Как читать результат

Например, `Строка 100: would_update` и следующий объект:

```json
{
  "C": "Воркута",
  "K": "ЖКХ и благоустройство",
  "L": "Работы начаты",
  "N": "Началась замена коммунальных сетей."
}
```

Это пример планируемых значений для C100, K100, L100 и N100. В режиме
`--dry-run` таблица не меняется. Пропущенный столбец не требует записи:
он уже заполнен, сведений нет или новое значение совпадает со старым.
`\n` в JSON обозначает перенос строки внутри ячейки.

| Событие | Значение |
|---|---|
| `would_update` | Подготовлены изменения без записи |
| `write_pending` | Изменения запланированы, подтверждения ещё нет |
| `updated` | Запись подтверждена и проверена чтением |
| `no_changes` | Анализ выполнен, менять ячейки не нужно |
| `skipped` | Пустой текст либо все разрешённые поля заполнены |
| `manual_review` | Ответ заблокирован или не прошёл проверку после повторов |
| `format_retry` / `classification_retry` | Повтор из-за формата / временной сетевой ошибки |
| `complete` / `stopped` | Завершение прохода / остановка по ошибке |

В итоговой строке `selected` — все строки периода; `analyzed` — число отправленных
на анализ новостей; `updated` и `would_update` — количество строк с записью
и с планируемой записью. `errors` — отклонённые ответы, `unresolved_stage` —
случаи, где стадия не определена и допустимой подстановки нет. Нулевое число
ошибок подтверждает техническую корректность, но не гарантирует смысловую
точность извлечения: для оценки качества проверяйте результат по тексту.

## Если запуск остановился

| Сообщение | Что проверить |
|---|---|
| Нет файла ключа / ошибка авторизации | Наличие своих локальных файлов, правильный ключ и `--scope` |
| Выбранная модель недоступна | `.env/bin/python main.py --list-models` и имя модели |
| Не найдены списки K6/L6 | Правила выбора в таблице и их ссылки на «Справочники» |
| Google Sheets HTTP 403 | Доступ сервисного аккаунта и включённый Sheets API |
| Изменились строки или справочники | Завершить другие операции с таблицей, затем перечитать её новым запуском |
| GigaChat HTTP 429 | Подождать, проверить ограничения ключа и отсутствие параллельных запросов |
| GigaChat HTTP 500/502 или ошибка соединения | Временный сбой API/сети; повторить после восстановления доступа |
| Google Sheets: неопределённый результат записи | Проверить строку и журнал: запись могла примениться без подтверждения |

HTTP-ошибки не повторяются автоматически. Повторы сетевых ошибок относятся
только к запросу анализа, а не к получению списка моделей или токена.
После сбоя уже подтверждённые записи сохраняются. Повторите тот же период;
автоматического перехода к последней строке или воспроизведения журнала нет.
Не включайте `--overwrite` только ради продолжения: он разрешает пересчёт
ранее заполненных значений. Если строки переставлялись, ищите нужную новость
по прямой ссылке из журнала, а не только по прежнему номеру.

|---|---|
